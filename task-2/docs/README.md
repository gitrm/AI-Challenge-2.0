# Gatherwave

A lightweight platform for running free, community-style events end to end —
publish an event page, collect RSVPs, hand out QR tickets, check people in at
the door, and gather feedback afterward.

This README is a usage guide for the four main flows. For project goals and
decisions, see `report.md`.

> The initial build plan (`.lovable/plan.md`) was generated by **Claude Opus
> 4.7** from the task description, then implemented in Lovable.

---

## Getting started

1. Open the app and sign in (email + password, or Google).
2. Anyone can browse `/explore` without an account. Everything else (RSVP,
   hosting, tickets) requires a signed-in user.

---

## Flow 1 — Publish an event

1. Click **Become a host** in the top nav.
2. Fill in host name, slug, contact email, optional logo and bio. The slug
   becomes your public host page at `/hosts/{slug}`.
3. From the **Host dashboard** (`/host`), click **New event**.
4. Fill in:
   - Title, description, cover image
   - Start / end date and time + time zone
   - Venue address **or** an online URL
   - Capacity (used for RSVP + waitlist)
   - Visibility: **Public** (appears in Explore) or **Unlisted** (link-only)
   - Free / Paid (Paid is disabled — coming soon)
5. Save as **Draft**, then click **Publish** when ready. You can later
   **Unpublish** or **Duplicate** the event from the same screen.
6. Share the public URL: `/event/{eventId}`. Open Graph + Twitter card
   metadata are generated automatically for nice link previews.

### Inviting team members

From `/host/members`, generate an invite link and pick a role:
- **Host** — full management (events, gallery moderation, CSV export, members)
- **Checker** — limited to the check-in screen for that host's events

The invitee opens the link, signs in, and is added to the host.

---

## Flow 2 — RSVP

1. A guest opens an event page at `/event/{eventId}`.
2. They click **RSVP**.
   - If signed out, they're sent to `/auth` and returned to the event after
     signing in.
   - If the event is full, they're added to the **waitlist** (FIFO). When a
     seat opens (cancellation, or capacity increase), the next person is
     promoted automatically and sees the change in-app.
3. Confirmed attendees can **Cancel RSVP** at any time before the event ends.
4. Past events show an **Ended** badge and hide the RSVP button.

---

## Flow 3 — Ticket

1. After RSVPing, the attendee sees their ticket on the event page and on
   `/tickets` (My Tickets).
2. The ticket includes:
   - A unique 8-character **ticket code** (e.g. `A1B2C3D4`)
   - A **QR code** rendered from that code
   - **Add to calendar** — downloads an `.ics` file that opens in Apple
     Calendar, Google Calendar, Outlook, etc.
3. `/tickets` lists every upcoming ticket the user has, sorted by start time.

---

## Flow 4 — Check-in

1. A Host or Checker opens the event in the host dashboard and clicks
   **Check-in**, or navigates to `/host/events/{eventId}/check-in`.
2. Two ways to check someone in:
   - **Scan** — point a camera at the QR code (uses the browser's
     `BarcodeDetector` where available).
   - **Enter code manually** — type the 8-character ticket code and press
     Enter. Manual entry is always available; a camera is not required.
3. The page shows live counters: **Going / Waitlist / Checked-in**.
4. Duplicate scans of the same code are detected and rejected.
5. The most recent successful check-in shows an **Undo** button if the
   checker scanned the wrong person.

### CSV export

From the event's host dashboard, click **Export CSV** to download attendees
with: `name`, `email`, `rsvp_status`, `checked_in_at`. Values are properly
quoted, so the file opens cleanly in Excel and Google Sheets. A reference
file is included as `sample-attendees.csv`.

---

## After the event

- **Feedback** — once the event ends, attendees see a 1–5 star rating + an
  optional comment on the event page. Aggregated rating + responses appear
  in the host dashboard.
- **Gallery** — attendees can upload photos. Uploads are queued as
  *pending* and only become public after a host approves them in the
  **Moderation** tab.
- **Reports** — anyone signed in can report an event or photo. Reports show
  up in the host's moderation queue, where the host can hide the item.

---

## My Events

Users with any host role see `/events` (My Events), which aggregates every
event across every host they belong to, with filters by host, date range,
and free-text search. Quick actions adapt to the user's role on each event
(e.g. Checkers only see Check-in).

## Tech notes

- TanStack Start (React 19 + Vite) on Cloudflare Workers
- Lovable Cloud (Postgres + Auth + Storage) for backend
- All access control enforced via Postgres RLS + a few SECURITY DEFINER RPCs
  (`rsvp_to_event`, `cancel_rsvp`, `redeem_invite`)

## UX details

- Every host/event/check-in/edit screen has a **Back** button so navigation
  is never a dead end.
- Date filters on Explore use a calendar popover (no raw `mm/dd/yyyy`
  inputs).
- CSV export is RFC-4180 quoted so attendee lists open cleanly in Excel
  and Google Sheets.
- A subtle cursor-reactive gradient background runs on every page; it's
  GPU-composited and does not impact interaction performance.
